# 차도 위로 지나가는 만남의광장~KSPO DOME 입체 보행 인도·육교 및 보행 겸용 차도 망 반영

- 날짜·시각: 2026-11-25 13:58 KST
- 누가: antigravity-주인
- 관련 Issue/PR: 없음

## 요청 해석
- 사용자가 표시한 올림픽공원역(만남의광장) ↔ 상가동 북동측 보행광장 ↔ KSPO DOME·핸드볼경기장 앞 광장 구간은 **보행자 전용 인도**이며, 그 중간에서 공원 내부 차도(`1230085700`, `양재대로.강동대로사이길`) **위로 인도가 입체 교차(육교)** 한다.
- 아울러 하부 차도를 포함한 모든 차도는 기본적으로 보행자가 걸을 수 있는 구조임을 지도 표시와 데이터(추후 도보 경로 탐색용 네트워크)에 함께 반영한다.

## 바꾼 것
- `data/processed/osm_park_paths_raw.json`, `scripts/33_build_pedestrian_network.py` (신규), `web/data/pedestrian_overpass.geojson` (14KB, 지도 즉시 표시용), `web/data/pedestrian_network.geojson` (다층 보행 그래프):
  - 모든 차도(서울시 도로 58구간 `links.json`·`link_shapes.geojson` 및 공원 내부 차도)를 `kind="road_walkable"`, `walkable=true`, `vehicle=true`, `fromLevel=0, toLevel=0`으로 수록해 전 차도 보행 가능 규칙을 반영했어요.
  - 만남의광장~KSPO DOME 보행 인도 광장 다각형(`haneol_promenade_poly`), 차도 위 육교 데크 다각형(`haneol_overpass_deck`, `level=1`, `baseHeightM=4.4`, `topHeightM=5.4`, `crossesOverRoadId="1230085700"`), 그리고 `0 → 1 → 1 → 0` 입체 층 분리 간선을 구축해 하부 차도(`level=0`)와 육교 상판(`level=1`)이 평면에서 섞이지 않고 입체 교차하도록 구성했어요.
- `web/assets/map3d.js`:
  - `roads` 레이어 **위**에 `ped-overpass` 레이어(`ped-promenade-fill`, `ped-promenade-border`, `ped-overpass-deck-flat`, `ped-overpass-rails`, `ped-walkway-spine`, `ped-overpass-3d`)를 올려, 위에서 내려다볼 때(`pitch=0°`)나 3D 기울임 상태(`pitch=56°`) 모두에서 보행 인도·육교가 차도 위로 지나가도록 표시했어요.
  - 도로·보행 인도 클릭 팝업과 범례(`보행 인도(차도 위 육교)`, `차도: 보행 가능`)도 함께 반영했어요.
- `web/assets/common.js`:
  - 평면 SVG 지도(`drawRoadMap`)에서도 하부 차도 위에 보행 인도·육교 상판이 올라가도록 그렸어요.
  - 추후 도보경로 기능에서 외부 유료 API 없이 바로 부를 수 있도록 `loadPedestrianNetwork()`와 다층 다익스트라 탐색 함수 `findPedestrianRoute(net, from, to)`(`{ meters, minutes, usedOverpass, coordinates }`)를 추가했어요(예: `올림픽공원역 → KSPO DOME` 546m·약 7분, `usedOverpass: true` 확인).
- `web/index.html`, `docs/context.md`, `docs/data_scope.md`: 스크립트 캐시 버전(`?v=ped1`), 배경·결정 기록, 데이터 출처 표 갱신.

## 확인한 방법
- `python3 scripts/check_all.py` 실행 → JS 14개·파이썬·JSON·필수 `id` 오류 0건, 경고 0건 통과.
- 로컬 정적 서버 + Playwright(360px 및 지도 화면)에서:
  1. `map` 화면 3D 지도 레이어(`ped-promenade-fill`, `ped-overpass-3d` 등)가 `roads` 레이어 위에 정상 렌더링되어 차도 위로 보행 인도·육교가 지나가는지 스크린샷과 레이어 순서로 확인했어요.
  2. 브라우저 안에서 `loadPedestrianNetwork()` → `findPedestrianRoute(net, "올림픽공원역", "KSPO DOME")` 호출 시 `usedOverpass: true`로 육교를 통과하는 경로가 계산되고, 하부 차도(`1230085700`) 위의 두 지점 간 탐색 시에는 지상 차도(`usedOverpass: false`)로 직진하는 입체 분리를 확인했어요.

## 결정과 이유
- 모바일 지도 진입 속도를 해치지 않도록 지도 시각 표시에는 경량 `pedestrian_overpass.geojson`(14KB)만 즉시 불러오고, 전체 공원 보행 그래프(`pedestrian_network.geojson`)는 추후 도보경로 탐색 함수(`loadPedestrianNetwork()`)가 호출될 때만 지연 로드하게 나눴어요.
- 사용자 말씀대로 기존 도보 시간·점선 표시(`walk_tmap.json`·`walk_routes.geojson`)는 그대로 유지하고, 추후 도보경로 개편 시 `findPedestrianRoute()`로 바로 전환·활용할 수 있게 준비했어요.

## 건드리면 안 되는 것
- `pedestrian_network.geojson` 간선의 `fromLevel` / `toLevel`(`0` vs `1`) 및 `u` / `v` 노드 ID(`L0_*`와 `L1_*` 분리): 하나로 합치면 하부 차도와 상부 육교가 공중에서 평면 교차해 버려요.
- `map3d.js`에서 `roads` 레이어 뒤에 `ped-overpass-*` 레이어를 추가하는 순서(바꾸면 차도가 다시 육교 위로 덮어 그려짐).
