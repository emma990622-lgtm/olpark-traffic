# 출차 곡선·실시간 카드에 입차·출차 절반/90% 예상·실제 선, 카드 이름 '실시간 입출차 감지'

## 요청 해석
- ① 운영자 '공연 후 출차 곡선'에도 실시간 카드처럼 실제 절반·실제 90%·절반 예상·90% 예상 선 ② 카드 이름 '공연 당일 실시간 출차 감지' → '공연 당일 실시간 입출차 감지' ③ 입차도 분석해 예상 선 ④ 사람이 할 일은 미리 알리기.
- 해석: 출차 곡선(과거 자료)에서 '예상' = 고른 날 공연 시작 + 지난 공연 전체 중앙값(공연 시작 시각만 보고 미리 예측), '실제' = 같은 시작 시각 지난 공연들의 중앙값. 입차는 '관객 차 절반·90%가 들어온 시각'으로 분석하고, 실시간 카드에는 공연 전 입차 예상 선(띠)을, 지난 공연 다시 보기에는 실제 입차 선을 넣음. 실시간 '입차 감지'(들어오는 중 몇 %인지)는 분모(오늘 올 관객 차 수)를 알 수 없어 넣지 않음.

## 바꾼 것
- `scripts/inout_common.py`: `ENTRY_FROM=-360, ENTRY_TO=30`, `entry_timing(x, s)` → 입차 절반·90% 시각(시작 기준 분). 관객 차 = 시작 6시간 전~30분 뒤 입차, 2시간 넘게 머묾, 시작 1.5~7시간 사이 출차, 150대 이상일 때만.
- `scripts/14_live_exit_calib.py`: 공연마다 `in50`/`in90`(10~12월은 그 시간대 기록 90% 이상 받은 공연만), 출력에 `entry`(half/most p25·med·p75·n), `entryBacktest`(한 공연씩 빼고 중앙값으로 맞혀 본 평균 오차·15분 이내 비율), `entryMethod`. 지난 공연 곡선 범위 −30 → **−180**분부터(`series.fromMin`).
- `scripts/18_exit_curves.py`: 공연마다 15분 입차 곡선(그날 12:00~다음날 01:00 들어온 차, 가중), 출차 절반·90%(09 `analyze`와 같게, 모든 출입구)·입차 절반·90%. 그룹에 `inMed/inP25/inP75/inN`, `actual{in50,in90,exit50,exit90: {med,n}}`, 그룹별 `dates[]`에도 네 값. 전체 `predict{...: {p25,med,p75,n}}`, `timingMethod`.
- `web/assets/live_exit.js`: 이름·설명, 입차 KPI 2개(절반·90%가 들어오는 시각 예상, 6개 KPI), 그래프 −180분부터·입차 예상 띠/점선(주황), 출차 예상 글자 '출차 절반/90% 예상', 다시 보기에서 실제 입차·출차 선(초록), 공연 전 상태 문구에 입차 예상 시각, 출처에 입차 방법·오차. `cfg.entry`가 없으면(예전 JSON) 입차 부분만 빠지고 그대로 동작.
- `web/assets/operator.js` `drawCurves`: 그래프 높이 300, 입차 곡선(주황) + 곡선 옆 '입차'/'출차' 글자, 예상 띠·점선 4개(이날 시작 기준), 실제 초록선 4개(그룹 시작 기준), 설명에 이날 예상 시각 4개·실제 시각 4개·세로선 범례·`timingMethod`. 띠를 먼저 그리고 선·글자를 나중에, 글자에 흰 테두리.
- `web/operator.html`: 카드 제목·설명 바꿈(id 그대로).
- `web/data/exit_curves.json`: 클라우드에서 새 형식으로 다시 만듦(**2024년 7월만**). `live_exit.json`은 그대로(PC 실행 뒤 `entry`가 생김).
