# 운영자 화면 출구 비중 합계가 약 110%로 나오던 문제 수정

- 날짜·시각: 2026-11-19 23:30
- 누가: Claude(claude.ai 채팅) + 저장소 주인
- 관련 Issue/PR: 없음 (`docs/context.md` 현재 진행 상황의 미해결 항목)

## 요청 해석
- 운영자 화면 "출구별 대응 참고" 표의 관객 차량 비중이 7개 출구 합 약 110%로 보이는 것을 고친다. 숫자 신뢰도(심사 핵심) 문제라서, 합이 정확히 100%가 되고 계산 방법이 화면에 드러나게 한다.

## 바꾼 것
- 원인: 출구별로 "그 출구가 나온 공연만"의 비중 **중앙값**을 따로 구했다. 드물게 쓰인 출구(서2·남3·남4·서1문, 4~13회)는 쓰인 날만 보니 비중이 부풀고, 출구마다 중앙값을 따로 잡아 합이 100%가 될 수 없었다(실제 110.1%).
- `scripts/09_exit_profile.py`
  - 공연별 출구 집계에서 15대 미만 출구도 **비중에는 넣음**(시간 t50·t90만 15대 이상일 때)
  - `aggregate_gates()`: 공연마다 출구 비중(합 100%) → 공연 평균, 안 쓰인 공연은 0%. 절반 이상 공연에서 쓰인 출구만 따로, 나머지는 "그 밖의 출구"(`members`에 출구 이름·횟수). `pct`는 합이 정확히 100이 되게 반올림. `p25`·`p75` 범위 추가. `gateMeta`(공연 수·방법) 추가.
  - `--from-json`: 원본 없이 `web/data/exit_profile.json`의 공연별 결과로 출구 집계만 다시 하기(원본 2025 파일은 주인 컴퓨터에만 있음).
- `web/data/exit_profile.json`: `--from-json`으로 다시 만듦. 동2문 38.1→**39%**, 북2문 30.4→**30%**, 남2문 23.5→**26%**, 작은 출구 4개 각 4~5% → **그 밖의 출구 5%**. 합 110% → **100%**.
- `web/assets/operator.js` `drawGates()`·`drawBrief()`: `pct` 사용, "보통 35~42%" 범위 표시, "그 밖의 출구" 아래 출구 이름, 시간 없음은 "—", 설명 문구(계산 방법·공연 61회)를 새로 씀.

## 확인한 방법
- `python scripts/check_all.py` ✅
- 로컬 서버 + 브라우저(1280px)로 운영자 화면을 열어 표 확인: 39%·30%·26%·5%, 범위·출구 이름 표시, 콘솔 오류 없음.

## 결정과 이유
- 공연마다 같은 무게(공연 평균)로 계산: 차가 많은 날 한두 번이 전체를 좌우하지 않게. 출구가 안 쓰인 날은 0%로 넣어야 "평소 비중"이 된다.
- 드문 출구는 따로 보이면 요원 배치를 잘못 이끌 수 있어 "그 밖의 출구"로 묶음(어떤 출구인지는 아래 줄에 표시).

## 건드리면 안 되는 것
- `exit_profile.json`의 `gates.*.pct / p25 / p75 / members`, `gateMeta` — 운영자 화면이 읽음. 이름 바꾸면 JS도 같이.
- 예전 결과 파일처럼 공연별 `gates`에 작은 출구가 빠져 있어도 남은 몫을 "그 밖의 출구"로 넣는 처리(`aggregate_gates`의 `left`)는 유지.
