# 프로젝트 배경 (모든 AI가 작업 전에 먼저 읽는 파일)

규칙은 `AGENTS.md`, 데이터 범위는 `docs/data_scope.md`, 디자인 규칙은 `docs/design.md`에 있다.
이 파일은 "규칙이 아닌 배경": 무엇을 왜 만들었는지, 데이터가 무슨 뜻인지, 이미 정한 것이 무엇인지.
새로 정한 것이 다음 작업에도 영향을 주면 맨 아래 "결정 기록"에 한 줄 추가한다(누구의 AI든).

## 1. 무엇을 만드나
- 한국체육산업개발 2026 공공데이터 활용 경진대회 출품작. 제출 마감 12/1 18:00.
- 주제: 공연 전후 주차·교통 혼잡을 예측해 **운영자의 현장 대응**과 **관객의 방문·귀가 선택**을 돕는다.
- 심사에서 가장 중요한 것: 공공데이터를 실제로 썼는지, 숫자를 믿을 수 있는지(출처·기간·방법 표시), 현장에서 쓸모가 있는지.

## 2. 화면 두 개
| 화면 | 파일 | 누가 | 핵심 기능 |
|---|---|---|---|
| 관객 | `web/index.html` + `assets/audience.js` | 휴대폰(360px) | 공연 고르기 → 공연장(KSPO DOME, 올림픽홀, 우리금융아트홀 등)별 도보 거리·지도 표시, 주차장 추천, 환승주차 탭(공연장 갈 때 / 나올 때), 귀가 시 출차 몰림 안내 |
| 운영자·기관 | `web/operator.html` + `assets/operator.js` | PC(1280px) | 3D 지도(`map3d.js`, MapLibre), 공연 2시간 전~2시간 후 시간 슬라이더, 도로 혼잡, 게이트별 출차 비율, 도로 자료 검증 패널, 주차장 만차 요약 |
- 두 화면이 같이 쓰는 함수는 `assets/common.js` (장소 불러오기, 환승 시간 계산 `transferTotal`/`transferOut`, 지하철 혼잡 모델 `CROWD`, 주차 대수 보정 `parkActual`, 도로 지도 `drawRoadMap`).
- `/api/*.js`는 Vercel 서버 함수(외부 API 중계, 키는 환경변수). 로컬(`run_web.bat`)에서는 `/api`가 안 되므로 실패해도 화면이 깨지면 안 된다.

## 3. 데이터 파일 (`web/data/`) — 무엇이고 어디서 왔나
| 파일 | 내용 | 출처·방법 |
|---|---|---|
| `events.json` | 공연 일정(공연장, 시작 시각) | 올림픽공원 공식 행사 일정 |
| `places.json` | 돔·주차장·역 위치 | 직접 정리 |
| `walk_tmap.json`, `walk_routes.geojson` | 주차장·역 → 각 공연장 도보 시간·경로 | TMAP 보행자 경로 (`scripts/05`) |
| `transfer_tmap.json` | 환승주차장 경로 | TMAP (`scripts/06`) |
| `station_drive.json` | 환승주차장(천호·잠실·복정·신천유수지) → 공원 운전 시간, 공연 시간대 예측 | TMAP 예측 경로 (`scripts/08`) |
| `links.json`, `link_shapes.geojson` | 도로 58구간과 모양 | 서울 실시간 도시데이터 + TMAP (`scripts/07`) |
| `exit_profile.json` | 공연 후 출차 곡선(50%·90% 빠지는 시간), 게이트 비율 | 2024-07 + 2025 입출차(88% 받은 시점), 공연 70회 (`scripts/09`) |
| `exits_2024_07.json`, `park_profile.json` | 2024년 7월 공연일 출차·주차 대수 | KSPO 입출차 215,528행 (`scripts/11`) |
| `congestion_summary.json` | 주차장 구역별 만차 시각 | 공공데이터포털 주차장 혼잡도 (`scripts/12`, `13`) |
| `road_check.json`, `road_source_check.json` | 도로 자료 검증(TOPIS vs 도시데이터, TMAP 비교) | `scripts/10` |
- 실시간 수집(공연일 도로·주차)은 별도 저장소 `olpark-collector`가 GitHub Actions로 저장한다.

## 4. 알고 있어야 할 데이터 함정
- **실시간 주차 `parking_sum`은 부풀려져 있다.** 출차 기록이 안 닫힌 장기 차량이 섞여 새벽에도 1,000대 넘게 나온다(실제 새벽 약 60대). 화면에는 `parkActual()`로 보정한 값을 쓴다. 원값을 그대로 "주차 중"으로 보이지 않는다.
- **주차장 혼잡도 자료의 `등록시간`은 분 자리에 월, 초 자리에 일이 들어가 있다(전부).** 시 단위로만 믿는다.
- 2025 입출차(KCISA)는 다운로드 중이라 비율만 쓰고 대수는 쓰지 않았다. 다 받으면 다시 계산한다. (11/19 기준 약 88% 받음. 문화공공데이터광장 점검으로 11/22 18시 이후 이어받기. 기록이 날짜순이 아니라 여러 날에 섞여 있어서 받은 만큼으로도 모든 공연일을 볼 수 있다.)
  - 서버가 특정 자리에서만 계속 오류(502)를 내면 그 10줄은 건너뛰고 `data/raw/kcisa_inout_2025.gaps.txt`에 기록한다. 분석·화면에 건너뛴 줄 수를 함께 밝힌다.
- "평일 2배" 같은 단정 표현은 피한다. "같은 시간대 평일 대비"처럼 기준을 붙인다.
- 2024-07 기준 일부 날 주차 대수가 총 면수(2,120면)를 넘는다. 원인 미확인(아직 없음 처리).

## 5. 이미 정한 것 (바꾸려면 이유를 보고서에 적기)
- 관객 화면은 "~해요"체, 쉬운 말. 운영자 화면은 짧은 명사형도 가능.
- 상태는 색만으로 구분하지 않는다(글자·아이콘 같이). 혼잡 3단계는 원활 / 서행 / 정체.
- 환승주차 '공연장에서 나올 때' 탭에는 "공연장 나오기 N분"을 넣지 않는다(사용자 요청으로 뺌).
- 데이터가 없으면 숫자를 만들지 않고 "아직 없음"으로 보인다.
- 새 라이브러리·빌드 단계는 넣지 않는다.

## 6. 현재 진행 상황 (바뀌면 고쳐 쓴다 · 마지막 갱신 2026-11-19 밤)

**일하는 방식**
- 역할 구분 없음. 누구의 AI든 `AGENTS.md` 작업 순서대로 하고, 끝나면 `docs/handoff/`에 인수인계 노트를 새 파일로 남긴다.
- `main`에 올리면 바로 실제 사이트에 반영. PR로 올리는 도구는 점검 통과 + 노트가 있으면 자동으로 합쳐진다(`.github/workflows/auto_merge.yml`).
- 오케스트라(orchestra.bat, 구글 시트 작업함)는 11/19에 없앴다.

**데이터**
- KCISA 2025 입출차: 약 88%(2,128,000 / 2,411,225줄)에서 멈춤. 문화공공데이터광장 점검이 11/22 18시까지 → 그 뒤 주인 컴퓨터에서 `run_kcisa.bat`으로 이어받고 `run_exit_profile.bat`으로 출차 분석을 다시 돌린다.
- 출차 분석(`exit_profile.json`, 88% 기준): 공연 70회(2024년 7월 7회 + 2025년 63회), 관객 차 40,746대. 몰리기 시작은 공연 시작 후 중앙값 170분, 그때부터 절반이 빠지는 데 32분, 90%는 73분. 화면에 "2025 자료 약 88% 기준"을 밝힌다.
  - 출구 비중(11/19 고침): 공연마다 출구별 비중(합 100%)을 구해 평균, 안 쓰인 공연은 0%. 동2문 39% · 북2문 30% · 남2문 26% · 그 밖의 출구(서2·남4·남3·서1문) 5% = 100% (출구 기록이 있는 2025 공연 61회). 다운로드 완료 뒤 `run_exit_profile.bat`으로 다시 계산하면 같은 방식으로 나온다.
  - 예측 정확도 점검(11/19, 공연 70회 leave-one-out): 몰리기 시작 시각 오차 평균 ±29분, 절반 출차 ±14분, 90% 출차 ±30분. 요일·시작 시각·차량 수·같은 공연 다른 날로는 거의 나아지지 않음 → 공연 종료 시각(런타임)과 당일 실시간 감지가 정밀도의 열쇠.
- 도로 검증(`road_check.json`): 11/19 긴 도로 이동시간 비교를 고침(교차로 대신 오른쪽 차로 점, 유턴 경로 제외). 첫 결과 긴 도로 8개, 서울시와 TMAP 이동시간 차이 중앙값 30%. 짧은 구간 등급 일치율은 신호 때문에 낮음(22%) → 검증 근거는 긴 도로 비교로 쓴다. 공연 종료 시각(11/21·22)과 평일 퇴근 시간에 GitHub Actions가 자동 실행.
- 새벽 주차 기록(수집기 저장소 `data/parking_night.csv`): 11/18 1,085대, 11/19 1,130대(실제 약 60대) → 안 닫힌 기록이 계속 쌓임. 화면은 `parkActual()`로 보정.

**화면**
- UI/UX 1차 전면 개편 반영(KRDS 기반, `docs/design.md` 참고).

**앞으로 일정**
- 11/21(금)·22(토) 공연: 자동 수집 + 현장 보정(가능하면 게이트 통과량·출차 대기 줄 관찰)
- 11/22 18시 이후: KCISA 나머지 받기 → 출차 분석 최종
- ~11/26: 간단한 예측 모델, 11/27~29 공연 예측값을 미리 고정
- 11/27~29: 예측 vs 실제 비교(심사용 정확도 근거)

## 7. 결정 기록 (최신이 위)
- 2026-11-19 밤: 오케스트라와 AI별 역할 구분을 없앰. 모든 AI가 같은 작업 순서(`AGENTS.md`)를 따르고, 인수인계는 `docs/handoff/` 노트(한 작업 한 파일)로 한다. 승인(Merge) 없이 `main` → 실제 사이트 바로 반영, PR 도구는 점검 통과 시 자동 합침. (아래 11/18·11/19 오케스트라·방식 A 기록은 이것으로 대체됨)
- 2026-11-19: UI/UX 전면 개편(KRDS 접근성·타이포 기반 + 관객 화면 Toss 지표 스트립·카카오T 실시간 주차 게이지·Citymapper 경로 단계 칩 + 운영자 화면 관제 KPI·교차검증 박스·A4 인쇄 양식) 및 `docs/design.md`(CSS 변수 체계, JS↔CSS 클래스 계약표, 보호 `id`/`data-*` 목록) 신설. 공모전 심사 기준에 맞춰 환승주차를 '정체 회피' 대신 '출구 혼잡 분산'으로 표현 다듬고, 운영자 도로 검증 번호 누락(`①→③` → `<ol>` 자동 번호)·실시간 문구 중복 표시·다회차 공연일(`12/24` 등) 회차 표기·3D 지도 외곽 마커 잘림 수정.
- 2026-11-19: 팀 작업은 각자 자기 AI + GitHub Issue/PR 인수인계가 기본(`docs/팀_작업법.md`). 오케스트라는 선택. 저장소 공개 전환.
- 2026-11-18: 오케스트라 도입. 작업마다 `orchestra/runs/<id>/handoff.md`(인수인계 노트)를 스크립트가 쓰고, 모든 AI가 먼저 읽는다.
