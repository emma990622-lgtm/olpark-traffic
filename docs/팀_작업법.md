# 팀 작업법 — 각자 자기 AI로 고치고, GitHub로 인수인계하기

두 사람이 동시에, 각자 쓰는 AI(Claude Code, Antigravity, Codex 등)로 작업한다.
누구 컴퓨터가 켜져 있을 필요가 없다. 인수인계는 GitHub의 **Issue(할 일)**와 **PR(수정 제안서)**로 한다.

```
Issue에 할 일 적기 → 내 브랜치 만들기 → 내 AI로 고치기 → 화면 확인 → Commit·Push
→ PR 올리기(설명은 AI가 양식대로) → Codex 자동 리뷰 + 미리보기 확인 → Merge → 실제 사이트 반영
```

## 1. 처음 한 번만 (팀원)
1. 메일이나 GitHub 알림으로 온 **저장소 초대(Invitation)를 수락**한다.
2. **GitHub Desktop** → File → Clone repository → `emma990622-lgtm/olpark-traffic` 선택 → Clone.
3. 쓰는 AI 도구에서 이 폴더를 연다.
   - Claude Code: 폴더에서 `claude` 실행 (`CLAUDE.md`를 자동으로 읽음)
   - Antigravity: 폴더를 작업 공간으로 열기 (`AGENTS.md`·`GEMINI.md`를 읽음)
   - Codex: 폴더에서 `codex` 실행 (`AGENTS.md`를 읽음)
4. 화면을 내 컴퓨터에서 보려면 `web\run_web.bat`을 두 번 누른다 → http://127.0.0.1:8000
   (내 컴퓨터에서는 실시간 자료(`/api`)가 안 나와도 정상이다.)

## 2. 매번 작업 순서
| 순서 | 어디서 | 할 일 |
|---|---|---|
| 1 | GitHub 웹 | **Issues** 탭에서 할 일을 고르고 오른쪽 **Assignees**에 나를 지정한다(같은 일을 둘이 하지 않게). 없으면 **New issue → 작업 요청**으로 만든다. |
| 2 | GitHub Desktop | **Current branch: main** 상태에서 **Fetch origin → Pull origin**으로 최신을 받는다. |
| 3 | GitHub Desktop | **Current branch → New branch** → 이름 예: `minji/parking-full-badge` (영어·숫자·하이픈) |
| 4 | 내 AI | 아래 **"시작할 때 붙여 넣을 말"**을 넣고 작업시킨다. |
| 5 | 내 컴퓨터 | `python scripts/check_all.py`로 기본 점검(❌ 없어야 함), `web\run_web.bat`으로 화면을 열어 확인한다. 관객 화면은 브라우저를 휴대폰 폭(360px)으로 줄여서 본다. |
| 6 | 내 AI | **"끝낼 때 붙여 넣을 말"**을 넣어 PR 설명을 받는다. |
| 7 | GitHub Desktop | 왼쪽 아래에 한 줄 요약을 쓰고 **Commit to 내브랜치** → **Publish branch**(처음) 또는 **Push origin**. |
| 8 | GitHub Desktop → 웹 | **Create Pull Request**(또는 Preview Pull Request) → 웹에서 설명 칸에 AI가 쓴 PR 설명을 붙여 넣고 **Create pull request**. |
| 9 | GitHub 웹 (PR) | 몇 분 뒤 **Codex 리뷰**와 **Vercel 미리보기 주소**가 댓글로 달린다. Codex가 지적한 게 있으면 내 AI에게 고치게 하고 다시 Commit·Push(같은 PR에 자동으로 붙는다). |
| 10 | GitHub 웹 (PR) | 미리보기를 서로 확인한 뒤 **Merge pull request** → 1~2분 뒤 실제 사이트가 바뀐다. 그다음 **Delete branch**. |
| 11 | GitHub Desktop | **Current branch → main**으로 돌아와 **Fetch origin → Pull origin**. 다음 일은 다시 2번부터. |

## 2-1. ChatGPT Codex(클라우드)로 작업할 때
Codex는 이 저장소에서 **기능·디자인·데이터·문서 전반을 맡는 담당**이다(`AGENTS.md` "AI별 역할"). 검수만 하는 게 아니다.
GitHub Desktop 없이 브라우저만으로도 작업할 수 있다.

**처음 한 번**
1. 저장소 주인이 보낸 **초대(Collaborator)를 수락**한다. (수락해야 Codex가 이 저장소에 PR을 올릴 수 있다)
2. [chatgpt.com/codex](https://chatgpt.com/codex) → GitHub 연결(내 GitHub 계정으로 승인).
3. **환경 만들기**: Codex 설정 → Environments → New environment → `emma990622-lgtm/olpark-traffic` 선택, 기본 브랜치 `main`.
   - 설치 명령(Setup script)은 비워 둔다. 분석 스크립트까지 돌릴 거면 `pip install pandas numpy`.
   - 저장소가 목록에 안 보이면: 저장소 주인이 GitHub에 **ChatGPT Codex Connector** 앱을 이 저장소에 설치해야 한다(주인 할 일).

**매번**
1. GitHub **Issues**에서 할 일을 고르고 Assignees에 나를 지정한다.
2. Codex에 아래처럼 맡긴다(환경: olpark-traffic, 브랜치: main).
   ```
   AGENTS.md와 docs/context.md를 먼저 읽고, GitHub Issue #번호를 처리해 줘.
   (Issue 내용 붙여 넣기)
   끝나기 전에 python scripts/check_all.py를 돌려서 ❌가 없게 하고,
   PR 설명은 .github/pull_request_template.md 양식의 칸을 모두 채워 줘.
   오래 지킬 결정은 docs/context.md 결정 기록에, 디자인 규칙은 docs/design.md에 한 줄 추가해 줘.
   ```
3. 결과(바뀐 코드·설명)를 보고 **Create PR**을 누른다.
4. PR에 **Vercel 미리보기 주소**가 댓글로 달리면 휴대폰 폭·PC에서 화면을 확인한다.
5. 고칠 게 있으면 PR 댓글에 `@codex 이 부분 이렇게 고쳐 줘`라고 쓴다 → 같은 PR에 고친 커밋이 더해진다.
   (`@codex review`라고만 쓰면 고치지 않고 **리뷰만** 단다.)
6. 서로 확인 후 **Merge** → 실제 사이트 반영.

**클라우드 Codex가 못 하는 것**
- 인증키가 필요한 스크립트 실행(TMAP·KCISA·공공데이터포털 받기). 이런 일은 PR "넘길 일"에 "주인 컴퓨터에서 run_○○.bat 실행"으로 적는다.
- 내 컴퓨터 화면 띄우기 → 대신 PR의 Vercel 미리보기로 확인.

## 3. AI에게 붙여 넣을 말

**시작할 때**
```
이 저장소의 AGENTS.md와 docs/context.md를 먼저 읽어 줘.
그다음 아래 할 일을 해 줘. 지금 브랜치에서만 작업하고, 커밋은 하지 마(내가 할게).
끝나기 전에 python scripts/check_all.py를 돌려서 ❌가 없게 해 줘.
끝나면 무엇을 바꿨는지, 화면에서 어디를 보면 되는지 알려 줘.

할 일 (GitHub Issue #번호):
(여기에 Issue 내용을 붙여 넣기)
```

**끝낼 때**
```
작업 끝났어. .github/pull_request_template.md 양식으로 PR 설명을 써 줘.
오래 지킬 결정이 있었으면 docs/context.md "결정 기록"에, 디자인 규칙을 새로 정했으면 docs/design.md에 한 줄 추가해 줘.
```

## 4. 카카오톡과 GitHub 나눠 쓰기
AI는 카카오톡을 못 읽는다. 그래서 **정한 것만** GitHub에 남긴다.

| 무엇 | 어디에 |
|---|---|
| 의견, 아이디어, 일정 상의 | 카카오톡 |
| 하기로 한 일 | GitHub **Issue** (한 줄이라도) |
| 이번 수정의 내용·이유·넘길 일 | **PR 설명** (AI가 양식대로 작성) |
| 오래 지킬 결정 (예: "만차는 빨간색+글자") | `docs/context.md` 결정 기록 (내 AI에게 "기록해 줘") |
| 디자인 규칙 (색 뜻, 간격) | `docs/design.md` |

## 5. 충돌 피하기
- **같은 화면을 둘이 동시에 크게 고치지 않는다.** Issue의 Assignees로 누가 하는지 보이게 한다.
- **작게 자주** PR을 올리고 빨리 Merge한다. 하루 넘게 붙잡고 있으면 충돌이 커진다.
- 작업 시작 전에 꼭 main 최신을 받는다(2번).
- PR에 **"This branch has conflicts"**가 뜨면: GitHub Desktop에서 내 브랜치 상태로 **Branch → Update from main** → 충돌 파일이 나오면 내 AI에게 "main과 충돌 난 부분을 두 쪽 의도를 다 살려서 정리해 줘"라고 한 뒤 Commit·Push.

## 6. 하지 말 것
- `main`에 바로 Commit·Push (실제 사이트가 검토 없이 바뀐다)
- 인증키·비밀번호를 코드·문서·Issue·PR·카톡 캡처에 올리기 (저장소가 공개다)
- `data/raw/` 원본 수정, `set_keys.bat`·`delete_keys.bat` 수정
