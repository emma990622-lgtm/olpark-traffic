# 팀 작업법 — 각자 자기 AI로 고치면 바로 사이트에 반영

- **역할 구분 없음.** 누구든, 어떤 AI(Claude Code, Antigravity, ChatGPT Codex)든 무엇이든 고친다.
- **승인(Merge) 단계 없음.** `main`에 올라가면 1~2분 뒤 https://olpark-traffic.vercel.app 이 바뀐다.
- 대신 **인수인계 노트**를 꼭 남긴다. AI는 카카오톡과 다른 사람의 대화를 못 본다. `docs/handoff/`의 노트와 `docs/context.md`만 보고 이어서 일한다.

```
main 최신 받기 → AI에게 맡기기(시작 문장) → 점검 → 인수인계 노트 → 올리기 → 1~2분 뒤 실제 사이트 반영
```

## 방법 1. 내 컴퓨터에서 (GitHub Desktop + Claude Code / Antigravity / Codex 앱·CLI)

**처음 한 번**
1. 저장소 초대(Collaborator)를 수락한다. (팀원)
2. GitHub Desktop → File → Clone repository → `emma990622-lgtm/olpark-traffic`.
3. 쓰는 AI 도구에서 이 폴더를 연다. 규칙 파일(`AGENTS.md`)은 AI가 알아서 읽는다.

**매번**
1. GitHub Desktop: **Current branch가 `main`**인지 보고 **Fetch origin → Pull origin**.
2. AI에게 아래 **시작 문장**을 넣고 할 일을 맡긴다.
3. AI가 점검·인수인계 노트까지 끝내면, GitHub Desktop에서 바뀐 파일을 보고 **Commit to main → Push origin**.
   (AI에게 "커밋하고 push까지 해 줘"라고 해도 된다. 그때는 AI가 `git pull --rebase` 후 push한다.)
4. 1~2분 뒤 실제 사이트에서 확인한다. 이상하면 같은 방식으로 다시 고친다.
   - Push가 "rejected"로 막히면 그사이 상대가 먼저 올린 것. **Fetch → Pull** 후 다시 Push(겹치는 부분이 있으면 AI에게 "충돌 정리해 줘").

## 방법 2. 브라우저에서 (ChatGPT Codex 클라우드, chatgpt.com/codex)

**처음 한 번**
1. 저장소 초대 수락 → chatgpt.com/codex에서 GitHub 연결.
2. 환경(Environment) 만들기: 저장소 `emma990622-lgtm/olpark-traffic`, 브랜치 `main`, 설치 명령은 비워 둔다.
   - 저장소가 안 보이면 저장소 주인이 GitHub에 **ChatGPT Codex Connector** 앱을 이 저장소에 설치해야 한다.

**매번**
1. Codex에 **시작 문장** + 할 일을 넣는다(환경 olpark-traffic, 브랜치 main).
2. 결과를 보고 **Create PR**.
3. 끝. GitHub가 자동으로 점검하고, **통과하면 바로 main에 합쳐서 실제 사이트에 반영**한다(`.github/workflows/auto_merge.yml`).
   - 점검에 걸리면 PR에 이유가 댓글로 달린다 → PR 댓글에 `@codex 위 점검 문제 고쳐 줘` → 고쳐지면 다시 점검 → 통과하면 자동 반영.

```
진행 상황이 바뀌었으면 docs/context.md "현재 진행 상황"도 고쳐 줘.

할 일:
(여기에 할 일. GitHub Issue가 있으면 번호와 내용)
```

## 카카오톡과 GitHub 나눠 쓰기
| 무엇 | 어디에 |
|---|---|
| 의견, 아이디어, 일정 상의 | 카카오톡 |
| 하기로 한 일 (선택) | GitHub **Issues** — 누가 하는지 Assignees로 보이게 하면 같은 일을 둘이 안 한다 |
| 무엇을 왜 바꿨는지, 다음 사람이 이어서 할 일 | `docs/handoff/` 인수인계 노트 (AI가 씀) |
| 오래 지킬 결정 (예: "만차는 빨간색+글자") | `docs/context.md` 결정 기록 (AI에게 "기록해 줘") |
| 지금 어디까지 했는지 | `docs/context.md` 현재 진행 상황 |
| 디자인 규칙·클래스 | `docs/design.md` |

## 충돌 줄이기
- 같은 화면을 둘이 동시에 크게 고치지 않는다(카톡으로 "나 지금 운영자 화면 해" 한마디).
- 작게 고치고 자주 올린다. 시작 전에 꼭 최신을 받는다.

## 하지 말 것
- 인증키·비밀번호를 코드·문서·노트·카톡 캡처에 올리기 (저장소가 공개다)
- `data/raw/` 원본, `set_keys.bat`·`delete_keys.bat` 고치기
- 인수인계 노트 없이 올리기
